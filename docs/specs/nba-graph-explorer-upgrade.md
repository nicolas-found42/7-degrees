# Upgrade the NBA/BAA graph explorer: visual clarity, shortest chains, filters, and evidence drawer

## Problem Statement

Dense orange edge bundles obscure player nodes and labels when a well-connected NBA/BAA player is selected. Concentric layout packs thousands of players onto thin rings without a meaningful unselected center. Controls below the canvas are cumbersome, especially on a phone.

The graph page cannot answer how two players connect, although its JSON APIs already calculate exact shortest teammate chains. Opening separate evidence pages interrupts exploration, and repetitive raw descriptions obscure the proof and its limitations.

Users need era and teammate focus, pair connections, and per-hop evidence without losing their place. Keyboard access, accessible text, and accurate source coverage gaps are required.

## Solution

Upgrade the existing Rust/WASM graph explorer in four phases:

1. Improve edge hierarchy, labels, node sizing, and era guides so selected players and their relationships remain legible.
2. Refine concentric layout into deterministic radial bands, add an optional ego-network view, and animate layout changes with reduced-motion support.
3. Add searchable Player A and Player B controls, exact shortest-chain highlighting, a text-accessible chain breadcrumb, random pairs, and composable era/franchise filters.
4. Move controls above or inside the canvas, improve mobile touch interaction, and present structured relationship proofs in a contextual evidence drawer while preserving standalone evidence URLs.

The default view continues to load the whole evidenced network, including isolated player nodes. Focus, filters, and chain highlighting are reversible views over that same graph. The current pinned snapshot contains 5,106 player nodes and 101,395 teammate edges; those figures are a baseline for this snapshot, not constants to embed in general application logic. A degree of separation is exact within the evidenced graph. Historical source coverage remains incomplete, so missing edges may shorten a historical chain or connect currently unreachable players.

## Implementation Decisions

### Architecture, contracts, and state

- **Extend the current stack.** Keep Axum HTML, the deterministic Rust graph, shared graph facts, and Rust/WASM canvas. Generated binding/loader JavaScript and browser-test transport remain acceptable. Add no JavaScript graph/UI framework, database service, or paid semantic dependency.
- **Reuse existing modules.** Extend graph-page composition, player search/catalog, shared payloads, canvas interaction/rendering, layouts, and provenance. Reuse graph-core shortest chains and supported fixture/report-backed routers. The graph owns identity, distances, degrees, teammate edges, and proof data.
- **Preserve graph semantics.** Keep undirected teammate edges and stable player IDs. Same canonical franchise in non-overlapping periods does not establish an edge. Existing admitted proof classes are certified positive dated roster overlap, a shared official dated team game, and appearance-count arithmetic guaranteeing shared team games. Do not convert an appearance proof or game witness into a full dated roster tenure.
- **Default and derived views.** The initial graph payload includes every player and admitted teammate edge with no selected chain. Rendering filters and ego view do not delete graph data or change shortest-path search. Counts distinguish loaded totals from currently emphasized/visible totals. Existing whole-network invariants remain true for the payload and default view; tests that prohibit all focused views or in-page evidence must change for this upgrade.
- **State ownership.** Maintain distinct canonical Player A and Player B IDs, layout mode, camera transform, hovered item, highlighted chain, era set, optional selected-player franchise, ego toggle, chain request status, and drawer state. Panning or centering a breadcrumb player changes camera inspection without changing the connection endpoints. Canvas node selection changes Player A and recomputes the chain when Player B is set.
- **DOM contracts.** Preserve `#graph-canvas`, `#graph-minimap`, `#graph-tooltip`, `#graph-player`, `#canvas-status`, `#graph-selection`, and the embedded `#graph-payload`. Preserve `data-layout` values `era`, `concentric`, and `force`. Add Player B as `#graph-target`, chain status/breadcrumb as `#graph-chain`, and evidence dialog as `#edge-evidence-drawer`. Move existing camera/layout controls without removing their accessible names or existing IDs. The enhanced `#graph-player` is the accessible Player A combobox; its server-rendered equivalent remains a native form control.
- **Routes and compatibility.** Keep `/` as the explorer and `/graph` as its compatibility alias. Keep `/edge?from=<id>&to=<id>` as independently renderable evidence and preserve source-record routes. Continue existing network, connection, shortest-alternative, edge, coverage, and search JSON interfaces; preserve their error handling, limits, pagination, and source coverage fields. This upgrade intentionally replaces the current rule that explorer player/pair parameters are always inert: `player` selects Player A, and a complete `from`/`to` pair initializes a chain on the whole-network page. `from` takes precedence over `player`; a lone `from` selects A, a lone `to` fills B, and `depth` and `all` remain compatibility parameters with no rendering effect. Unknown IDs produce an accessible error without dropping the whole-network payload.
- **Deep links and fallback.** Support server-rendered GET forms for selecting the pair and returning the ordered chain, degree, error/no-chain state, and real evidence anchors. Expose a standard source-player selector when enhancement is unavailable. A chain URL does not need to serialize camera, filters, or layout. Those states survive drawer navigation within the enhanced session. Reloading a standalone `/edge` URL renders standalone evidence. No persistent storage or new account feature is required.
- **Shared metadata.** Supply explicit debut-season metadata rather than parsing display text, canonical franchise lists, and degree where required. Derive degree from the complete admitted graph, never from a filtered view. Fixture nodes with unknown historical debut data receive an explicit unknown category and stable layout fallback; synthetic day numbers must not masquerade as calendar seasons. Additive metadata retains defaults for compatible fixture/custom payloads. Any shared connection DTO used by the enhanced UI must preserve the actual API's coverage and disconnected-certainty fields.

### Phase 1: rendering and visual hierarchy

- **Edge hierarchy.** At logical/CSS pixel scale use background alpha 0.03/width 0.5; two-hop alpha 0.055/width 0.5; direct focus-to-teammate alpha 0.23/width 0.85; hovered/inspected edges and active chain links alpha 1.0/width 2.2. The first three preserve source ranges 0.02–0.04, 0.04–0.07, and 0.18–0.28. Draw important categories last. Preserve orange selection and blue `#176896` chains. While a chain is active, set ordinary nodes/edges to alpha 0.05; chain and hovered/inspected edges retain full opacity. Inspected non-chain edges remain distinguishable from the blue chain.
- **Curves and hit testing.** Give focused edges deterministic quadratic Bézier curvature with a perpendicular midpoint offset proportional to length. Use canonical ordered endpoint IDs to fix the bend direction. Reuse the same geometry for rendering and pointer hit testing; clicking a curved visible edge must not require clicking its former straight chord. Curvature must not obscure endpoint nodes or cause a zero-length/self-link error. Keep distant background rendering efficient.
- **Labels.** Draw ordinary labels in dark slate `#0f172a` with a 3-pixel rounded halo matching the canvas background. Draw selected, hovered, and active-chain labels as dark, white-bold-text pills with an era border, above their node. Deduplicate states when one player has several priorities. Reuse existing density-aware decluttering and width measurements; reserve measured bounding boxes for important labels before placing ordinary labels. Important labels must not be removed by ordinary-label culling. At close distances, offset/stack important badges rather than knowingly painting one over another; they may be clipped when the user pans their nodes out of the viewport.
- **Node size.** Base normal node radius on `baseRadius + log2(1 + degree) * scaleFactor`, with fixed positive visual constants shared across layouts. Keep a positive base radius for isolates, clamp effective zoomed sizes to readable bounds, and maintain a larger pointer/touch hit region than tiny visual dots. Degree is the count of distinct evidenced teammate edges, including the full network even when some context is hidden.
- **Era guides.** In Era lanes only, draw subtle alternating decade columns behind edges and labels, with `1940s` through `2000s` and `2010s+` headers. World-space column boundaries follow the same debut placement as nodes. Headers follow horizontal camera movement while remaining pinned to the canvas top during vertical panning. The final category covers 2010 onward. Era colors remain labeled, and unknown debut metadata is not presented as a known decade.
- **Accessibility of faint context.** Full-opacity selection/hover/chains, readable badges, labeled controls, and text chain/evidence provide actionable information. Color alone must not convey selection, chain membership, or filters.

### Phase 2: layout refinements

- **Concentric center.** Center the layout on Player A. If Concentric rings is requested with no A, focus the player picker and announce “Select a player to use Concentric rings.” Leave the previously active layout and its state selected until a player is chosen; then apply the pending concentric request. Do not silently choose a player on the user's behalf. An empty snapshot disables this request with an explanatory state.
- **Radial bands.** Place one-hop nodes in an inner annulus and two-hop nodes in a non-overlapping middle annulus, with deterministic radial distribution that spreads density across each band's width. Angular ordering uses shared canonical franchise with the focus where evidenced, then debut season, then stable player ID. For multiple eligible franchise groups use a stable canonical order; unmatched/unknown groups follow known ones. Two-hop nodes may group by an evidenced predecessor's franchise connection, with stable tie-breaking. Keep distances based on the full admitted graph. Place three-plus-hop and unreachable context outside the ego bands and render it at node alpha 0.05.
- **Ego mode.** Offer “Show ego network only (1–2 hops)” when A is selected, across layouts. Include A plus every player at distance one or two and the admitted edges whose endpoints lie in that set; do not silently apply the existing bounded neighborhood API's node/edge cap to this view. Fit that visible set with padding. A zero-neighbor selection fits the one selected node. Turning the toggle off restores distant context. An active shortest chain overrides hiding for all its nodes and links, and the status states that the chain remains included beyond two hops.
- **Deterministic force layout.** Retain the existing spring relaxation seeded from Era lanes. Identical snapshot, mode, and relevant selection yield identical final positions. View filters do not rerun a different graph layout merely because context is dimmed.
- **Transitions.** Interpolate node coordinates over 250 milliseconds using the browser animation-frame mechanism, and coordinate camera framing with the same motion preference. With `prefers-reduced-motion: reduce`, apply final coordinates and camera changes immediately. New layout requests supersede pending transitions from their current displayed positions. While a transition runs, node/edge hit testing and minimap projection follow the displayed positions, and cancellation cannot leave the UI showing the wrong `data-layout` value.

### Phase 3: chains, search, and filters

- **Player pickers.** Both enhanced pickers use combobox/listbox semantics, clear labels, explicit selected IDs, Up/Down navigation, Enter selection, and Escape dismissal. Selecting a candidate is distinct from typing or highlighting one. Keyboard input inside a picker must not trigger canvas pan/zoom shortcuts. Keep a native server-rendered selector/form fallback. Preserve deterministic lexical name/alias retrieval and duplicate-name disambiguation using season/franchise context plus canonical ID when necessary.
- **Picker search contract.** Extend existing search with optional `era=<decade>` and `franchise=<canonical-id>` filters rather than inventing a semantic-provider query requirement. Both filters are applied before result limiting; name/alias ordering remains deterministic. Recognize a bare supported decade token or an exact canonical franchise token as a context search in the UI. Provide explicit context-filter controls for combined name/era/franchise searches instead of guessing arbitrary natural-language syntax. Preserve no-match, ambiguity, total-match, and more-results information. Reject invalid filter values through the existing JSON error convention. A picker shows at most 20 suggestions at once and states when narrowing is needed. Unknown-debut nodes remain findable by name and are excluded only when a known-debut filter is requested. Request generations or cancellation prevent stale search results from replacing newer ones.
- **Path calculation.** When both canonical endpoints are set, request the existing `/api/connection` interface and use its exact unweighted shortest teammate chain. Do not implement a second pathfinder inside the renderer or ask Jev to find a path. Reuse the server's deterministic ordering for the default among equal shortest chains. Preserve `/api/paths` for API consumers, but alternative-chain browsing/ranking UI is outside this upgrade.
- **Chain lifecycle.** Clear the previous highlight as soon as the pair changes and show loading for the new pair. Accept a response only if it matches the current endpoint generation. Connected results render the returned ordered path and evidenced links, with `degree = number of links`. A self-pair renders one player, zero links, and degree zero. A disconnected result renders no highlight, distinguishes complete fixture disconnection from unresolved historical coverage, and offers another pair. A network/server failure offers retry and leaves ordinary graph navigation usable; it must not label an old path as current.
- **Chain framing and breadcrumb.** Make chain nodes and edges blue, retain selected-player identification through badges, dim ordinary context, and frame the path bounds with padding below the toolbar and beside an open drawer. The breadcrumb is an ordered, text-accessible representation containing names, degree, franchise, and a concise evidence summary per hop. Use real links for evidence URLs and buttons for camera-only player centering. Do not invent a season for a proof that lacks one. Long breadcrumbs wrap or scroll within their own region on phones without making the page overflow.
- **Random and clear.** Random pair samples two distinct canonical IDs from the full loaded player universe, including isolates, when at least two players exist; it may legitimately produce no chain. Disable it for zero or one player with an explanation. This explicit discovery action may be random; layout and graph facts remain deterministic for the chosen pair. Clear chain empties B, removes highlight/loading/error/breadcrumb, retains A, layout, and view filters, and restores normal focus emphasis without an unexpected camera jump. Re-selecting both endpoints frames the next result.
- **Era toggles.** All eight labeled debut-era toggles start enabled and expose `aria-pressed`. Enabled eras combine with OR; a disabled era dims its ordinary nodes to 0.05. Permitting no enabled eras produces a clear “No eras emphasized” state rather than deleting loaded data. Nodes with unknown debut are an explicitly labeled unclassified context, remain ordinarily visible with all eras enabled, and are dimmed when narrowing to selected eras. Selected/hovered/chain nodes take priority over dimming.
- **Franchise chips.** For Player A, expose one canonical franchise chip per known affiliation, with at most one active franchise filter. A chip emphasizes A's direct teammate edges admitted with that franchise and their counterpart nodes. Merely having played for the franchise in different periods does not qualify a counterpart as A's teammate. Use the full edge's admitted evidence classes, not only the single strongest summary already used for canvas links. Changing A clears this player-specific filter. Clicking an active chip clears it.
- **Filter composition.** Era and franchise emphasis combine with AND across categories, and match counts/status describe the composition. Chain/selected/hovered nodes and chain edges retain precedence and stay inspectable, including when ego view is active. Keep a visible filter summary and Reset filters action; reset enables all eras, clears the franchise, and disables ego mode. Filters never change the graph searched for the shortest chain. Fit whole network resets ego hiding and frames all loaded nodes, while retaining any era/franchise emphasis and active chain.

### Phase 4: controls, touch, and evidence

- **Primary toolbar.** Put A, B, Random pair, Clear chain, the labeled three-way layout control, and live selection/chain status above the canvas. Keep era toggles and franchise chips nearby. Represent the active layout in the control and `data-layout` consistently; preserve existing layout button IDs. The selected-player summary continues to state name, seasons, and canonical franchises.
- **Canvas and HUD.** Retain a 1000×600 logical coordinate system with backing pixels scaled for device pixel ratio and correct pointer coordinate conversion. Dock the 200×120 logical minimap at bottom left within the canvas container, with a translucent background and a legible orange viewport frame. Dock labeled Zoom in/out, directional Pan, Fit whole network, and Zoom to selected player controls at bottom right. Account for overlays when framing important nodes; prevent HUD pointer events from triggering canvas selection.
- **Minimap.** Show the whole network's context with low node opacity, plus active selection/chain where useful. The viewport rectangle reflects the current camera and usable graph area; clicking jumps the camera and dragging the rectangle pans it. Normalize input for CSS size and device pixel ratio. Reuse the main camera model so minimap and keyboard/button navigation cannot drift. When hidden on mobile, the minimap has no pointer or tab-focus interception. Button and keyboard camera navigation remain an equivalent accessible option.
- **Keyboard and announcements.** Preserve canvas Arrow-key pan, `+`/`-` zoom, and `f` fit while the canvas has focus. Do not capture shortcuts from controls, editable fields, or the dialog. Keep concise status announcements for loaded counts and zoom, selection, filter changes, chain results/errors, and evidence loading. Update live text only on meaningful changes, not every animation frame. The tooltip includes player name, era, canonical franchises, and evidenced teammate count; selection/breadcrumb text provides an equivalent non-hover route to relevant context.
- **Mobile.** At widths at or below 640 pixels, stack both pickers and the essential toolbar, collapse the minimap by default behind a labeled `aria-expanded` toggle, and keep camera controls compact with touch targets of at least 44×44 CSS pixels. The 390×844 reference viewport has no horizontal page overflow, blocked primary controls, or permanently obscured selected-player information. The evidence drawer occupies the available viewport width up to its desktop width and scrolls internally; coverage tables scroll within their container.
- **Touch gestures.** Use pointer capture and active pointer tracking for one-finger pan and two-finger pinch-to-zoom anchored at the gesture centroid. Suppress native page scrolling only within the interactive canvas; the rest of the page remains scrollable. A gesture moved beyond the drag threshold does not also click a node/edge. Handle pointer cancellation, released pointers, resize, and a transition from two fingers to one without a camera jump or a stuck drag.
- **Evidence navigation.** Intercept ordinary enhanced activation of an edge or breadcrumb evidence link and open a 420-pixel right-hand drawer without recreating the canvas. Keep real anchor hrefs so modified/new-tab activation and unenhanced navigation work. Reuse the same provenance-card presentation for drawer content and standalone evidence. Request a same-origin fragment from the existing `/edge` route using an optional `view=drawer` representation parameter; the default remains a complete HTML page, and error/no-edge states also have a valid fragment representation. Do not embed an entire duplicate document or duplicate graph IDs inside the dialog.
- **History.** On initial drawer open, push the canonical `/edge?from=...&to=...` URL and retain the previous explorer state in session/history state. Changing the inspected edge within the already-open drawer replaces that drawer entry rather than stacking unrelated modal entries. Browser Back or the close button/Escape returns to the prior explorer entry and restores its camera, pair, layout, and filters; Forward reopens the corresponding evidence. Refreshing or directly opening an evidence URL renders the standalone page. The fragment-only representation flag never appears in the shared canonical URL.
- **Dialog accessibility and recovery.** Use a labeled dialog, focus an appropriate heading/close control on open, keep focus within it while open, and make the underlying graph inert for keyboard/assistive interaction. Close on the labeled close button or Escape and restore focus to the triggering element, or to the canvas if that trigger no longer exists. Keep the same graph instance and camera behind it. Evidence requests carry pair/generation identity so a stale response cannot overwrite a later edge. On failure, show a retry action and standalone evidence link. Closing during loading must not reopen the drawer when a late response arrives.
- **Proof cards.** Each proof card names endpoints, canonical franchise, known season/date, proof type, records, and source version. Multi-season dated proofs show their interval; never manufacture a season. Keep multiple proofs distinct. Game-witness cards show original official dates/records without implying full roster duration.
- **Appearance overlap meter.** For count evidence show A's appearances `A/N`, B's appearances `B/N`, and the guaranteed minimum `A + B - N`, using the actual certified team-game total `N`. For example, 81 and 50 appearances over 82 team games guarantee at least 49 shared team games. Use bars/arithmetic and equivalent text; counts do not identify which specific games were shared. Label “82-game season” only when `N = 82`; otherwise label the actual season total. Never infer days or exact tenure boundaries from these counts. Preserve unknown/null overlap duration in API and displayed text.
- **Dated overlap meter.** For dated evidence show each certified roster interval and the intersection as half-open calendar intervals `[start, end)`, with end-exclusive wording and correct overlap-day totals. Use a proportionate timeline where useful, and keep complete text/source anchors. Synthetic fixtures show synthetic days, not fabricated historical calendar dates.
- **Coverage gaps.** Keep the overall incomplete-coverage warning visible outside the collapsed detail. Put “Coverage gaps for these players” inside collapsed native details, with a summary stating the available excluded-record count. Use a table with Player, Franchise, Season, Interval, Evidence class, and Reason; retain traceable record links in the relevant row. Show original class names such as inferred, unresolved, and cross-checked, and explain that excluded records are not admitted proofs. Unknown intervals/seasons have explicit text. Preserve bounded presentation: at most 100 rows per endpoint, deduplicate a self-pair, and say “Showing X of N” when truncated. Distinguish no listed exclusions from complete historical coverage. Normalize provenance display wording to the actual records; opaque citation placeholders and the source draft's mistaken `14` report prefix are not source evidence.
- **Performance and isolation.** Retain viewport culling, bounded label work, cached measurements, and efficient full-network edge passes. Stop animation work when settled. Chain/search/fragment work cannot freeze navigation, replace newer state, or duplicate listeners. Keep credentials server-side and source rendering escaped; no acquisition or pin refresh is required.

## Testing Decisions

- **Primary acceptance seam:** Extend real-browser journeys against Axum and built Rust/WASM: search/select, layouts, filters, camera/touch, chains, evidence, focus, history, and mobile. Reuse browser support and fixture/diamond/historical/full-report journeys; add no renderer mock or second harness.
- **Supporting contract seam:** Extend fixture/report-backed HTTP integration for connections, identity/context filters, payload compatibility, standalone/drawer evidence, proof arithmetic, coverage, errors, and GET forms.
